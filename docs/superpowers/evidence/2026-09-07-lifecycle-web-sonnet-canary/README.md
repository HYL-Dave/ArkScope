## Provider-Free Source Correction

The reader overrode `HTTPConnection.close()` with a forced socket shutdown.
CPython's `getresponse()` invokes `close()` when `response.will_close` is true
to transfer ownership to the response's file object, before its body is read.
The override therefore shut down a valid response during that ownership transfer.
Rejected headers also left a response-owned file object unclosed.

New regression tests use actual `HTTPConnection`/`HTTPResponse` parsing over a
local socket pair, delaying the body until after `getresponse()` returns. The
initial RED run is 8 failures/4 passes: ordinary fixed-length, chunked and EOF
bodies fail, with a persistent-connection positive control passing. The narrow
fix retains a separate transport handle for cancellation, inherits normal
connection close behavior and explicitly closes the response in final cleanup.
Real truncation is still rejected; abort/deadline still interrupt the detached
response-owned socket, rather than merely waiting for it to finish.

The source-focused GREEN run passes 81 tests. The same twelve wire owners are
also exercised through real TLS, hostname/certificate verification and a local
socket pair, using a throwaway OpenSSL-generated certificate. The combined
plain/TLS run passes 24 tests with no external connection or credential. The
test certificate/key are not archived. Full affected-set mutations and complete
backend verification are recorded separately in `verification.json`.
