## Important Findings

### I1: Namespace Aliases Bypass iXBRL Hidden-Content Exclusion

- Location: `src/sec_research/document_text.py:106` (`_DocumentHTMLParser._SKIP`), with inherited literal-tag handling at `src/lifecycle_public_sources.py:223`.
- The skip set recognizes only literal `ix:header`, `ix:hidden`, `ix:references`, and `ix:resources`. A document binding `xmlns:inl="http://www.xbrl.org/2013/inlineXBRL"` and using `inl:header/inl:hidden` instead is admitted and emits its hidden fact into canonical text. This reproduces for both HTML and XHTML MIME types: output is `HIDDEN FACT\nVisible fact.` instead of `Visible fact.`.
- Impact: hidden/non-display facts become ordinary text eligible for indexing, search, and pinned citations. The requirement to exclude iXBRL hidden header/data is not limited to the spelling `ix`; the implementer's declared namespace-alias limitation is an unapproved reduction in that requirement.
- Fix: resolve scoped namespace bindings for iXBRL hidden elements in the SEC refinement while preserving visible facts and lifecycle defaults. Add alternate-prefix and namespace-scope regression coverage; do not treat arbitrary similarly named HTML elements as iXBRL.
- Evidence: `task-1/test_independent_review_probe.py:8`; `task1-independent-review-probe-20260912-01/output.log:3` and `:10` show the two behavioral failures. Existing visible/hidden coverage uses only the literal `ix` prefix (`tests/test_sec_research_document_text.py:19`).

### I2: Any Duplicate Heading Incorrectly Ends TOC Ambiguity

- Location: `src/sec_research/document_text.py:342`, specifically unconditional `in_toc = False` at line 344.
- Encountering an already-seen section ID is treated as proof that the body has begun. In a document containing only `TABLE OF CONTENTS`, duplicate `ITEM 1. BUSINESS`, and then `ITEM 1A. RISK FACTORS` / `ITEM 2. PROPERTIES` with page numbers on separate lines, the latter two TOC entries become successful sections. No body section exists in this fixture.
- Impact: `item_1a` selects bytes `[52,77)` containing only the TOC heading and page number; `item_2` selects `[77,99)`. Only `item_1` receives an ambiguity gap. Exact byte arithmetic does not make these semantically valid sections, and downstream callers cannot distinguish them from an actual body index.
- Fix: do not clear TOC uncertainty merely because a heading repeats. Require independent evidence of a body transition, or conservatively omit subsequent uncertain sections with gaps while retaining whole-text access. Cover duplicates within a TOC, including page numbers on separate canonical lines.
- Evidence: `task-1/test_independent_review_probe.py:24`; `task1-independent-review-probe-20260912-01/output.log:17` shows the returned sections and missing ambiguity. Existing TOC coverage assumes that the first duplicate marks body content (`tests/test_sec_research_document_text.py:165`).
