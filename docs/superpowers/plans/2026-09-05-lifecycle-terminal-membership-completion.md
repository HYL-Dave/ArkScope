## Invariants

acquisition announcement. Never alias an acquisition target to the buyer.
Keep same-security renames attended until the separate automation gate passes.
Keep existing source history and applied activity; use the transition service,
including its open-position and state-digest guards. Removing a Former membership
must survive refresh/bootstrap/aliasing without removing manual/portfolio sources.

The prior census is evidence, not an installation. New schema/production changes
must have backup, exact preflight, idempotent commands and a verifiable receipt.
No provider calls, App restart, merge or push are part of offline implementation.
Existing user-owned untracked evidence and plans remain untouched.

Coverage must not invent historical membership from the first price timestamp or
count unavailable history as complete. Its existing current-universe retrospective
scope is made explicit; real missing bars retain an actionable backfill path.

## Installation Boundary

The V4 code intentionally rejects an old V3 lifecycle database. Installation is
explicit, with a create-only private backup, a profile-state-bound preview, a
separate SA-observation digest, and an atomic migration/bootstrap. Both automation
switches must be valid and false before backup or write. Changes to those switches
invalidate approval; unrelated credential fields are neither selected nor logged.
Do not merge and restart against V3 without the separately approved cutover.

The prior ARCH/LTHM/TA census did not establish an exhaustive successor history:
its ticker-event requests returned 404. Those observations cannot authorize an
automatic terminal transition. Fresh otherwise-complete delisting evidence can
support an explicitly attended historical decision; a complete automatic path
is covered with separate synthetic positive controls. Existing open positions,
active OTC evidence, fresh contradictory observations, and changed profile state
still veto application. No acquisition-to-buyer alias is created.

Opening coverage or its repair preview does not start collection. Explicit
confirmation binds the ticker set, dates, interval and local gap digest. Only
IBKR is used, without provider fallback. Completion re-reads stored bars; an
accepted job or successful collector return alone is not coverage success.
