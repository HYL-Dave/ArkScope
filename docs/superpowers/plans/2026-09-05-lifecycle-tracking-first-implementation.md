## 3. Contract To Implement

Keep these values separate in the internal typed result and public projection:

| Axis | Required distinctions |
| --- | --- |
| Listing | active, independently confirmed inactive, unresolved/conflicting |
| Continuation | confirmed, candidate, unavailable, ambiguous, not observed |
| Dates | old-listing end date versus continuation effective date |
| Authority | deterministic provider policy versus this action's human approval |
| Local effect | still tracked, prepared, approved/scheduled, applied, blocked |

`not observed` is limited to the retrieved material; it never means that no
successor has existed anywhere. Do not overload `successor_ticker` with both a
candidate and a confirmed replacement. Use a separately typed candidate field.

| Evidence and authority | Required outcome |
| --- | --- |
| Complete required inactive-listing checks; timeline unavailable | Offer old-listing retirement; preserve continuation follow-up |
| Same listing checks; different latest ticker without an old-to-new relation | Offer retirement independently; show candidate; do not alias |
| Positive current trading for the old listing, including OTC | No retirement; acquisition news does not override it |
| Missing/stale required listing evidence or conflicting identity | No automatic retirement; expose the actual missing/conflicting condition |
| Proven same-security relation with valid date and active successor | Offer reviewed continuation, not acquisition-to-acquirer substitution |
| Historical listing end before 2025 | Attended treatment, not newly granted automatic authority |
| Open position | Preserve the existing retirement veto and portfolio-safe continuation behavior |
| Mutation permission disabled | Decisions/proposals remain available; no automatic profile mutation |
| Clear validated web finding with new human confirmation | Governed attended action, even if the structured endpoint is still unavailable |

Evidence assurance and write permission are different axes. Raising decision
quality does not enable unattended mutation. An old `accepted` assessment is not
consent to a new web action, while valid deterministic automation remains a
separate authority.
